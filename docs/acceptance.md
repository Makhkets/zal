# Приёмка перед демонстрацией

Отметка означает фактическую проверку в указанной среде. **Локально** — настоящий FastAPI и SQLite с платёжным sandbox; **автотест** — временная БД и фейковый провайдер; **production** — публичный HTTPS с Platega. Проверка sandbox не доказывает банковскую оплату. В текущем каталоге 33 сеанса: к исходным 32 добавлен проверочный сеанс с тарифом 1 ₽. Исторические отчёты ниже сохраняют число сеансов на момент своей проверки.

На момент последней проверки банковская оплата человеком не выполнена, выданных production-билетов — 0. Реальное создание СБП-ссылки с итогом 1,03 ₽ проверено отдельно.

## Защита покупки

Следующие отмеченные проверки выполнялись с фейковым платёжным провайдером; production-доказательства указаны отдельно.

- [ ] Два независимых одновременных заказа с разными ключами на одно место: один успешен, другой получает 409 — не подменять проверкой двух запросов с одним ключом.
- [x] Повтор с одним `Idempotency-Key` возвращает тот же `order.id`; конкурентные повторы отправляют один POST провайдеру — автотест.
- [x] Тот же ключ с другим телом даёт `IDEMPOTENCY_CONFLICT` — автотест.
- [x] Неоднозначный таймаут POST не создаёт второй платёж; бронь сохраняется после рестарта — автотест.
- [x] Два одинаковых `CONFIRMED` и параллельная серверная сверка оставляют один билет — автотест.
- [x] Callback с неверным секретом отклоняется до сохранения события — автотест и production HTTPS 401.
- [x] Неверная сумма, валюта или привязка `transactionId` не выпускает билет — автотесты.
- [x] Callback до сохранения ответа создания обработан через проверенную серверную сверку — автотесты, включая комиссию провайдера.
- [x] Старый `CANCELED` не отменяет `paid` и не освобождает место — автотест.
- [x] При недоступном банке после истечения таймера место не продаётся повторно вслепую — автотест.
- [x] Возврат и спор меняют статус проверки билета; старые события не восстанавливают отозванный билет — автотесты без реальных возвратов.
- [x] Неверный `access_token` не открывает заказ — локальный интеграционный тест; без токена production отвечает 401.
- [x] В production недоступно ручное sandbox-подтверждение и нет `/__mock` в OpenAPI — публичный HTTPS и интеграционный тест.

- Проверены модели, связи и доступность всех 32 будущих сеансов: 2 кинотеатра, 8 фильмов, 2 зала по 282 места. Цены приходят от API в RUB.

- Маршрутов `/__mock` в OpenAPI нет; запрос страницы мока даёт 404, POST подтверждения — 405 от общего GET-маршрута приложения.
- SQLite находится на постоянном диске, `quick_check=ok`; БД и env имеют права 600. На момент проверки: 0 заказов, 0 билетов, 0 платёжных событий.
- Фоновая сверка включена с интервалом 15 секунд. Проверены настройки работающего процесса, запуск worker в lifespan и успешное завершение startup. Отдельного публичного heartbeat worker нет.
- Авторизация Platega проверена только через `GET /balance/all`: HTTP 200. Тело ответа, баланс и ключи не сохранялись и не выводились.

В 10:18 UTC публичный `https://cinema.makhkets.ru` прошёл проверку сертификата без исключений: health live200, фронтенд200, оба кинотеатра и 32 сеанса доступны. Через HTTPS также проверены отсутствие доступа к заказу без токена (401, no-store и no-referrer), отклонение неверного callback-секрета (401) и отключение мока (404).

Эта проверка не подтверждает завершённую покупку: создание СБП-платежа, оплата человеком в банковском приложении и получение билета остаются отдельным ручным этапом.
