# Промпт для ИИ фронтендера

Ты работаешь с Makhkets в ветке frontend репозитория ZAL. За 5 часов вдвоём нужно сделать сервис из docs/source/hackathon-brief.pdf, максимально закрыв критерии 31 балла. Твоя зона: apps/web, дизайн, Three.js/Web Audio, сценарии пользователя и презентация. jasperBLCK параллельно делает сервер в backend.

Сначала прочитай AGENTS.md, docs/plan.md, docs/criteria.md, docs/api.md, contracts/openapi.json, docs/architecture.md, docs/design.md, docs/presentation.md. Посмотри PNG-референсы в docs/design. Все поля API и координаты уже зафиксированы.

Реализуй React + TypeScript + Vite. Предпочитай простой CSS и Three.js без тяжёлого UI-kit. Сначала F1–F5 и F8 из плана, затем F6/F7. Работай маленькими завершёнными этапами и делай PR в main.

Запуск API для независимой работы: python3 scripts/mock_api.py. Мок имеет режим mock и не совершает платежей. Используй единый api/client и VITE_API_BASE_URL, чтобы заменить мок реальным сервером без изменения компонентов.

Построй путь: кинотеатр → сеанс → SVG-схема → 3D с выбранного места → checkout с email → внешняя оплата СБП → ожидание подтверждения → билет с QR и печатью. Все кинотеатры, цены, статусы и геометрия берутся из API.

Для любого seat_id используй Hall.seats[].position. Камера = position + eye_height по Y, смотрит на screen.center, FOV постоянный. SVG использует X/Z этих же точек. Проверь ряд 1 место 3, ряд 6 место 12, ряд 10 диван 7 и случайные места. Головы/кресла должны объяснять разницу видимости. Выход из 3D сохраняет выбор.

Стиль из PDF: тёмный зал, молочные крупные заголовки, оранжево-красный акцент, контурные кресла. Не заменяй это шаблонной белой карточной сеткой. Перенеси стиль и в 6 слайдов.

При покупке цена считается сервером. Отправляй session_id, seat_id, customer_email и один Idempotency-Key. Сохраняй order.id/access_token до перехода на Platega. После возврата опрашивай заказ; билет показывай только при paid. Реальное подтверждение не может происходить кнопкой в UI.

Состояния обязательны: loading, пустой список, ошибка/повтор, занятое место, чужая бронь, платеж создаётся, ожидается, проверяется, отменён/истёк, успешный билет, отзыв билета. При смене кинотеатра/сеанса сбрасывай зависимый выбор и отменяй устаревшие запросы.

Никаких секретов Platega в VITE_*, компонентах, .env фронтенда или репозитории. Ключи нужны только бэкенду. Открывай только payment_url, полученный от своего API.

Бонусы после работающего P0: звук от двух колонок по положению места; сравнение двух мест A/B с ценами и настоящими камерами. Используй собственный локальный аудиосигнал, кнопку включения и mute.

Проверь мобильный экран 390 px, desktop, клавиатуру, WebGL failure, повторный клик и 409. Собери проект. Перед каждым PR укажи готовые задачи и как их проверить. После первого этапа, примерно через 45 минут, интегрируй настоящий API — не откладывай до конца.
