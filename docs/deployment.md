# Запуск и размещение

Владелец: jasperBLCK. К концу второго часа нужен публичный HTTPS, потому что Platega отправляет callback на доступный извне адрес.

## Локальная разработка

Фронт на 5173, API на 8000. Vite проксирует /api в http://127.0.0.1:8000. Мок и настоящий API не запускать на одном порту одновременно.

~~~sh
cd apps/web
npm ci
npm run dev
~~~

Стартовый backend содержит только /api/v1/health; бизнес-endpoint реализует jasperBLCK:

~~~sh
cd apps/api
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --reload --env-file .env --port 8000
~~~

## Схема production

Выбрать уже доступную команде площадку с HTTPS и постоянным диском. Самый простой вариант — один сервер: собранный frontend и /api/v1 под одним доменом, SQLite в persistent volume. Подготовку начать рано; не откладывать регистрацию нового сервиса до финала.

Если frontend размещён отдельно, backend CORS разрешает только точный frontend origin, и обе стороны используют HTTPS. На статическом хостинге добавить rewrite для SPA-маршрутов; API не должен попадать под rewrite на index.html.

Не размещать SQLite на эфемерной файловой системе или в нескольких независимых репликах. Для выбранной площадки записать точные команды в этот файл после реализации.

## Порядок

1. Настроить DATABASE_PATH на постоянный каталог, PUBLIC_APP_URL на домен приложения, ORDER_TOKEN_SECRET на постоянный секрет.
2. Передать PLATEGA_* через секреты хостинга; PAYMENT_PROVIDER=platega включать только для настоящего адаптера.
3. Выполнить миграцию/seed без удаления существующих заказов.
4. Собрать frontend, поднять API одним worker. Отдельная периодическая сверка должна переживать рестарт через записи в БД.
5. Проверить /api/v1/health, /cinemas, доступность сеансов, прямые маршруты /sessions/... и /payment/return.
6. Согласовать используемый callback мерчанта, направить его на /api/v1/payments/platega/callback. Проверить доступность без браузерной авторизации.
7. Выполнить ручной платёж и проверку билета. Перезапустить приложение и снова открыть билет.

Не использовать локальный мок для публичной демонстрации реальной оплаты. Туннель может помочь при разработке callback, но временный адрес и спящий ноутбук ухудшают надёжность финального показа.
