# ZAL — билет с видом на экран

Сервис покупки билетов: выбрать кинотеатр и сеанс, примерить место в 3D, сравнить ракурсы и звук, оформить заказ и получить QR-билет.

**Frontend уже подключён к настоящему FastAPI и SQLite.** В каталоге два демонстрационных кинотеатра, восемь фильмов с настоящими постерами, 33 сеанса и два зала по 282 места. Браузерный путь покупки через sandbox, QR и сохранение заказа после перезапуска API проверены. Адаптер Platega реализован и покрыт автоматическими проверками; настоящая покупка СБП требует отдельного подтверждения человеком.

[Презентация PDF — 6 слайдов](docs/artifacts/zal-presentation.pdf) · [Запуск](docs/deployment.md) · [Проверки и критерии](docs/criteria.md). Публичный сайт — **https://cinema.makhkets.ru** (HTTPS, API в режиме live); состояние размещения фиксируется в [инструкции deployment](docs/deployment.md). Максимум задания — 24 базовых и 7 дополнительных баллов; оценку выставляет жюри.

## Что можно показать

- Живой 3D-зал и афишу: три карточки одновременно, поиск, жанры, выбор кинотеатра, светлую и тёмную темы.
- Одну геометрию для SVG-схемы и Three.js: любое кресло меняет положение камеры, есть фигуры зрителей, осмотр зала и обзорные ракурсы.
- Тестовый трейлер **Sintel** на экране зала и звук Web Audio, зависящий от расстояния до колонок. Это общий калибровочный ролик, а не трейлер каждого фильма афиши.
- Подбор места по предпочтению, сравнение двух видов с одного кадра трейлера и полноэкранный просмотр.
- Чат сеанса между посетителями: SSE, реакции, Unicode и BetterTTV-эмоуты. История последних 50 сообщений хранится в памяти одного процесса.
- Внешний read-only каталог Apple iTunes: реальные фильмы, постеры, превью и ссылки источника; без выдуманных сеансов и интеграции с кассами сетей.
- Серверную цену, атомарную бронь, идемпотентность, приватный доступ к заказу, QR и восстановление после рестарта.

## Локальный запуск

Требуются Python 3.12+ и Node.js 22+. Из корня клонированного репозитория:

```sh
cd apps/api
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
PAYMENT_PROVIDER=mock DATABASE_PATH=./data/zal-integration.db \
PUBLIC_APP_URL=http://localhost:5173 PUBLIC_API_URL=http://127.0.0.1:8000 \
ENABLE_EXTERNAL_MEDIA_NETWORK=0 ENABLE_BACKGROUND_RECONCILER=1 \
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

Во втором терминале из корня:

```sh
cd apps/web
npm ci
npm run dev
```

Открыть **http://localhost:5173**. API и постоянная БД настоящие, платёжный провайдер в этой команде — sandbox без списания денег. `scripts/mock_api.py` остаётся отдельным инструментом разработки; одновременно с API на порту 8000 его не запускать.

Приватный `apps/api/.env` не передаётся при клонировании. При необходимости создайте его из `.env.example` только при отсутствии существующего файла. Не перезаписывайте заполненный `.env`, не передавайте ключи во frontend и не добавляйте секреты в Git.

## Проверки

```sh
python3 scripts/check_contract.py
python3 scripts/smoke_mock.py
cd apps/api
.venv/bin/python -m unittest discover -s tests -v
```

Сборка frontend: `cd apps/web && npm run build`. CI запускает проверки контракта, backend-тесты и сборку. В интегрированной версии 65 backend-тест: каталог и доступ, SQLite/restart, гонки, повтор платежа/callback, неоднозначные ответы, суммы, спор и возврат, внешний каталог и чат. Платёжные тесты используют фейкового провайдера и не списывают деньги.

## Демопокупка

Афиша и схема показывают обычные тарифы **350 / 550 / 900 ₽**. При `DEMO_CHECKOUT_MINOR=100` сервер оформляет новую покупку за **1 ₽ до комиссии Platega**; для проверенной котировки итог — 1,03 ₽. Оформление явно показывает демосумму, затем цену афиши, скидку и комиссию. Сумма билета равна реально подтверждённой сумме. Существующие заказы сохраняют прежнюю сумму.

Поставляемый systemd unit включает этот режим для хакатона. Чтобы продавать по тарифам афиши, укажите `DEMO_CHECKOUT_MINOR=0` в `/etc/zal/zal.env`. Минимальная успешно проверенная сумма POST — 1 ₽; это не обещание неизменного лимита платёжного провайдера.

Чат закреплён справа на широком экране, сворачивается и запоминает выбор пользователя. На телефоне открывается отдельной панелью над нижней кнопкой покупки.
