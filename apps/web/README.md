# ZAL — фронтенд

React + TypeScript + Vite, Three.js, Web Audio, Motion. Палитра и композиция развиты из исходного PDF. Все кинотеатры, фильмы, цены, места и геометрия получаются из API; клиент не содержит ключей Platega.

## Запуск

Из корня репозитория в первом терминале:

```sh
python3 scripts/mock_api.py
```

Во втором:

```sh
cd apps/web
npm ci
npm run dev
```

Открыть **http://localhost:5173**. Именно localhost: на этот origin возвращает тестовый провайдер, а токен заказа хранится в sessionStorage. Мок работает только локально, явно обозначен в интерфейсе и не списывает деньги.

```sh
npm run build
```

## Что работает

- Афиша двух кинотеатров из API, иллюстрации фильмов и живой 3D-зал на главном экране.
- Интерактивный 3D-зал: вращение, масштаб, выбор кресла, обзор / от экрана / сзади / сверху. SVG-схема с клавиатурой использует ту же геометрию и сохраняет выбранное место.
- Вид с любого кресла на уровне глаз с фиксированным FOV. Контрольные места: 1/3, 6/12 и 10/диван 7. Занятые кресла с фигурами зрителей.
- Сравнение A/B: две камеры, цена, расстояние и отклонение от центра экрана. Пространственный синтезированный звук включается только кнопкой.
- Checkout с email, один Idempotency-Key на попытку, серверная сумма, внешний платёж и опрос состояния. Параметры URL не подтверждают оплату.
- Билет после `paid`, QR публичной проверки, печать, статусы недействительного билета. «Мои билеты» показывает заказы текущей браузерной сессии.
- Адаптация к телефону, фиксированная строка выбранного места, loading/error/empty, клавиатура, reduced motion, WebGL fallback.
- `/presentation`: шесть слайдов, клавиатура, заметки, fullscreen и печать. [PDF](../../docs/artifacts/zal-presentation.pdf).

## Подключение настоящего API — jasperBLCK

Контракт не изменён: [OpenAPI](../../contracts/openapi.json), [пояснения](../../docs/api.md). Единственная точка HTTP-запросов — `src/lib/api.ts`, типы — `src/lib/types.ts`.

По умолчанию `/api/v1` проксируется Vite на `127.0.0.1:8000`. Для другого адреса задать `VITE_API_BASE_URL` в локальном `.env` **до сборки**, например `https://your-api.example/api/v1`. В production удобнее единый origin: `/api/*` в API, остальные маршруты в `index.html`. При разных origin серверу нужны CORS для GET/POST, Authorization и Idempotency-Key.

1. Реализовать все endpoints контракта, включая health с `mode: live`.
2. Возвращать цену в целых копейках, `payment_url` только от провайдера, `access_token` при создании заказа.
3. Return URL: `https://<frontend>/payment/return?order=<order_id>`; возврат в той же вкладке. Платёж подтверждает сервер, после чего `/orders/:id` отдаёт `paid`, а `/orders/:id/ticket` — Ticket.
4. `verification_url` билета должен вести на `https://<frontend>/tickets/<token>`. Этот маршрут получает публичный Ticket из API и не показывает email.
5. Доступность обновляется каждые 10 секунд и при возврате фокуса. При 409 checkout закрывается и загружает актуальные места.
6. Для смены кинотеатров/сеансов/цен и конфигурации зала менять серверные данные, компоненты менять не требуется.

Один заказ — одно кресло или один диван. Реальные платежи, постоянная БД, переживание рестарта и публичный хостинг зависят от бэкенда. Сквозной путь фронтенда проверен на локальном моке; это не подтверждение готовности реальной Platega-интеграции.

## Проверка перед совместным демо

1. Выбрать кинотеатр, сеанс, кресло в 3D; перейти в схему и обратно — место сохранено.
2. Открыть три контрольных ракурса, затем произвольное кресло. Добавить два места к сравнению.
3. Включить звук в наушниках, проверить центр/бок и первый/задний ряд.
4. Оформить заказ, проверить отсутствие билета до оплаты, пройти провайдера, вернуться и открыть QR.
5. Повторить загрузку заказа; открыть приватный заказ без токена — доступ закрыт.
6. Проверить телефон 390 px, клавиатуру на схеме, ошибку сети и печать.
7. На настоящем API отдельно проверить реальную оплату, двойную покупку, повтор callback, возвраты и сохранность после рестарта.

## Проверено на текущей реализации

`npm run build`, проверки контракта и smoke мока проходят. Браузерные проверки в Chromium: desktop 1440×1000, mobile 390×844, полный путь тестовой покупки, QR и публичная проверка, отсутствие доступа к приватному заказу без токена, `paid=1` без эффекта, клавиатура модалки, печать билета (1 страница) и презентации (6 страниц 16:9).

Отдельно воспроизведены и устранены два сценария: быстрое переключение кресла перед открытием 3D/checkout и запоздалый ответ доступности. После исправления место в просмотре совпадает с checkout, а старый ответ не отменяет актуальный статус sold.

Axe не обнаружил нарушений на проверенных главном экране, выборе места, сравнении, checkout, билете и презентации. Текст поверх canvas и некоторых декоративных слоёв дополнительно проверен визуально. Это не заменяет проверку всех вспомогательных технологий.

Three.js загружается отдельным chunk (~144 КБ gzip); сборщик предупреждает о размере исходного chunk более 500 КБ. 3D требует WebGL; при его отсутствии доступна схема и покупка.
